> 本轮约束：到任务 4 的 AnimationState / BlendState 核心后停止，不继续推进任务 5–9。

## 状态摘要

AnimationState 的 fade/playhead 生命周期、action-before-weight-zero 顺序、fade 完成收尾、缓存时间入口、固定 timeline group cursor 遍历，以及 BlendState 权重预算已经接入并通过 workspace 测试。BlendState 的具体目标 pose 写入、timeline rebuild 所需的各轴创建与数值 blend 仍由任务 6 承接；当前不能据此宣称阶段 4 动画姿态已完成。

此停止点可作为“任务 4 状态核心已实现，任务 6 具体 timeline 轴待完成”的交接。任务 5 的 Animation API 已有先前实现，不要重复造一套；下一会话先核对本文件的未完成项和现有代码，再按原顺序继续。

## 本轮完成内容

### AnimationState

- `FadeState`、`SubFadeState` 与 `PlayheadState` 分开表达官方状态值；只有 playhead bits 为 `3` 才推进 state time。
- Fade 推进在 state timeScale 之前执行；负 dt 在 fade 层转正；fade-in/out progress、start/complete 事件种类、longer fade-out guard 和 progress continuity 已实现。
- Armature 推进处按 root state、`action_enabled` 和相应 listener gate 决定生命周期事件是否入队；核心仍只向 RuntimeCtx 缓冲，不 dispatch listener。
- Action timeline 在 `weight == 0` early return 前更新；零权重测试验证 action cursor/play state 仍前进。
- ZOrder 在零权重 early return 之后、普通 timeline groups 之前更新；六个普通 timeline group 按固定顺序遍历 cursor：Bone → BoneBlend → Slot → SlotBlend → Constraint → Animation。
- Fade 完成时运行 pose timeline 清理和 auto-fade-out；`push_timeline` 会将 `is_pose` 标志与 pose ID 集合保持一致。淡出开始时清除已有轴的 dirty 标记。
- 单状态且 fade 完成时保留 cache 结构：Action currentTime 按 `cacheFrameRate * 2` 量化并计算 cache frame index。多状态路径传 `cacheFrameRate = 0` 并将 armature cache index 置 `-1`。cachedFrames 的写侧仍未实现，见 P1-4。

### BlendState

- `BlendState::update/reset` 已按 TS 的 `dirty/layer/leftWeight/layerWeight/blendWeight` 预算公式实现；BlendState map 仅做 lookup，不决定 writer 遍历顺序。
- 覆盖首 writer、同层累加、高层消耗剩余预算、下层预算耗尽及逐帧 reset 的单测通过。

### 本轮补上的回归

- `zero_weight_state_still_advances_its_action_timeline`：验证 action 在 weight zero return 前推进；解除 weight gate 后验证 action 完成触发 auto-fade，以及单状态缓存帧入口。
- `fade_completion_removes_pose_timelines_but_keeps_animation_timelines`：验证只移除 pose axes，不误删普通 timeline。
- `fade_out_invalidates_all_existing_timeline_values`：验证淡出起始清除 timeline dirty 状态。
- 原有 pauseFadeIn、timeScale 独立 fade、fade 连续性、BlendState 和状态顺序测试继续通过。

## 明确未完成 / 不要误判

1. `AnimationState.timeline_dirty` 目前没有消费端；`RebuildAll` / `RefreshTargets` 尚未驱动 timeline rebuild。Bone/Slot/Constraint/Animation targets 的创建和维护要在任务 6 实现。
2. 六组循环现在推进通用 cursor，但**没有具体轴的 pose update / numeric blend**；目标 pose 的 dirty first-writer 初始化及同 BlendState target 去重还需要任务 6 的骨骼/插槽轴落地。
3. `timeline_states/{animation,bone,constraint,deform,slot,surface}.rs` 是占位模块；Action/ZOrder 虽已部分实现，需按任务 6/7 规格补合成 IR 和逐帧对拍。
4. cacheFrameRate/cacheFrameIndex 的状态路径保留了单状态入口，但不可变 `AnimationData.cached_frames` cache 写入、bone/slot cached indices 与数据复用仍是 P1-4；当前不支持宣称 cache 完成。
5. `BlendStateKey` 现在以 kind + target name 查找；任务 6 落地时核查是否应升级为强类型 target handle，并确认相同目标共享 accumulator、异目标不会碰撞。
6. 任务 5 的 Animation API 在当前工作树已存在部分实现（例如 play/config/goto/stop/fadeIn），但仍须对照规格完整验收；任务 4 本轮没有继续扩展它们。
7. listener dispatch、SOUND 双发、事件对象池化和正式逐帧 golden harness 属任务 5/7 后续边界；当前 RuntimeCtx 只缓存事件快照。
